# Career Quest

Веб-приложение для навигации развития сотрудника: профиль и прогресс к следующему грейду, до трёх объяснимых рекомендаций, отметка прохождения и HR-аналитика. Все демонстрационные данные синтетические.

## Запуск

Нужен Docker Compose. Из корня репозитория:

```bash
docker compose up --build
```

Откройте http://localhost:3001. API и Swagger: http://localhost:3000/docs. PostgreSQL хранит данные в Docker volume. Первый запуск собирает контейнеры и может занять несколько минут.

На странице **HR** нажмите «Добавить данные» и выберите четыре файла из `demo/`: `employees.json`, `events.json`, `skills.json`, `activity_history.csv`. Затем откройте профиль `E0028` в разделе сотрудника. На нём Public Speaking ниже остальных, но трижды пропущен; для Senior разрыв System Design равен двум уровням. Выполните рекомендованную активность и проверьте новый уровень навыка и готовность.

Можно загрузить файлы стартового кита тем же способом. Импорт принимает JSON-массивы или объект с ключом `employees`/`events`/`skills`, а историю — JSON или CSV с колонками `employee_id,event_id,status,date`. Данные навыков должны содержать требования целевого грейда в `requirements`, `grade_requirements`, `requirements_by_grade` или `levels` (ключ грейда либо роль → грейд). После первого импорта можно отдельно загрузить только `activity_history.csv`: сотрудники и события сохраняются. Если требования для навыка отсутствуют, временная цель равна текущему уровню +1, максимум 5. Импорт обновляет сотрудников с совпадающими ID в одной транзакции.

## Как устроено

- **Frontend:** Next.js, страница сотрудника и HR.
- **Backend:** NestJS, TypeORM, PostgreSQL. `POST /api/hr/import` загружает набор данных; `/api/employees/:id/recommendations` считает следующий шаг; `POST /api/activities/complete` применяет `gain` и `max_level` из события.
- **Рекомендации:** локальный контекстный ранжировщик оценивает разрыв до следующего грейда, реальный прирост события, историю похожих активностей и целевую аудиторию. До трёх допустимых событий возвращаются с факторами решения. Он работает без API-ключа и даёт повторяемый результат. Если задать `AI_PROVIDER=openai` и `OPENAI_API_KEY`, OpenAI выбирает порядок из уже проверенных кандидатов. Модель задаётся через `OPENAI_MODEL`, лимит ответа — через `OPENAI_MAX_TOKENS`; неизвестные ID отбрасываются, а при ошибке или таймауте 7 секунд используется локальный результат. Объяснение всегда строится из фактов датасета.
- **HR:** частые разрывы навыков, готовность, сотрудники без доступного шага и участие по событиям.

`readinessScore` = сумма `min(текущий уровень, требуемый уровень)` / сумма требуемых уровней × 100. Выполненное событие нельзя зачесть повторно. Данные о пропусках доступны только в личном профиле и HR-представлении.

## Как проверить вызов OpenAI

Смотрите серверные логи: `docker compose logs -f backend` (или консоль `npm run start:dev`). Запросите профиль с навыками и доступными событиями, например `E0028` после импорта `demo/`. Последовательность `OpenAI request started` → `OpenAI response received` → `OpenAI recommendation applied` подтверждает успешный вызов. В логе ответа есть `x-request-id` OpenAI и расход токенов, но нет API-ключа или содержимого профиля. `OpenAI fallback` показывает ошибку или недопустимый ответ. `Career AI skipped` означает отсутствие допустимых событий, а `OpenAI skipped` — выключенный провайдер или отсутствующий ключ.

Для профиля без навыков `/recommendations` возвращает `[]` ещё до OpenAI. Проверьте его через `GET /api/employees/:id` и убедитесь, что в `skills` есть навыки ниже требований следующего грейда. В Docker Compose ключ передаётся в backend из `OPENAI_API_KEY` при запуске контейнера; после изменения переменных контейнер нужно пересоздать.

## Проверка

```bash
npm ci
npm test -- --runInBand
npm run build
cd frontend
npm ci
npm run typecheck
npm run build
```

Роли в демо задаются заголовками `x-user-role` и `x-user-id`; это эмуляция авторизации для хакатона, не промышленная аутентификация. Для внедрения в банк нужны SSO/JWT, серверная привязка личности к роли и миграции вместо `synchronize: true`.
